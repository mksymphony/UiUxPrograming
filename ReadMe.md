# Virtual Character Studio · 중간고사 프로토타입

버추얼 캐릭터 제작 및 활용 정보를 소개하는 HTML/CSS/JavaScript 웹 프로토타입입니다. 실제 제작 신청이나 취소는 서버로 전송되지 않으며 **브라우저 내부에서 시연**합니다.

## 1. 서비스와 사용자 경험

- **서비스명:** Virtual Character Studio
- **주요 사용자:** 자신만의 버추얼 캐릭터를 만들거나 방송·VRChat·영상에서 활용하려는 사용자
- **목적:** 3D 제작, ARKit 페이스 트래킹, 방송 활용 정보를 안내하고 제작 신청 과정을 체험하도록 돕기
- **핵심 행동:** 캐릭터 이름과 활용 목적을 입력해 시연 신청을 완료하고, 완료한 기록을 조회하거나 취소
- **완료 조건:** 7주차의 5단계 신청 체험을 완료하면 내역에 새 기록이 생성되며, 사용자가 검색·상세 조회·취소 결과를 화면에서 확인할 수 있음

## 2. 7주차 결과물과 달라진 점 (중간고사 신규 기능)

7주차에는 **시작 → 이름 입력 → 목적 선택 → 내용 확인 → 완료**까지만 구현했습니다. 중간고사에는 이 완료 결과를 **'내 신청 내역' 목록에 추가하고, 검색·상세 보기·취소할 수 있는 사용 경로**를 추가했습니다. 이 신규 기능은 완료 화면의 '내 신청 내역 보기' 버튼 및 상단 메뉴에 연결되어 있으며, 저장 내용은 브라우저 `localStorage`에 보관됩니다.

기존 기능: 기능 탭 3개, 실시간 이름 미리보기와 글자 수, 안내 확인 체크박스, 입력 오류 안내, 이전 단계 수정, 완료 후 다시 시작을 유지했습니다.

## 3. 사용자 흐름

```text
[기존 7주차]
시작 → 이름 입력 → 활용 목적 선택 → 내용 확인 → 신청 체험 완료
                                                  ↓
[중간고사 신규]
'내 신청 내역 보기' → 완료 기록 목록 → 이름 검색/상태 필터
                                        ↓
                                  상세 다시 열기
                                        ↓
                              '체험 취소' → 취소 상태
```

- '처음부터 다시 시작하기'는 **현재 신청 입력 흐름**을 초기화하고, 기존 완료 기록은 남겨 새 신청을 또 체험할 수 있게 합니다.
- 완료 내역의 취소는 기록 상태만 `완료 → 취소`로 변경합니다. 실제 신청 서비스와 연동되지 않습니다.
- 저장 기록은 **이 브라우저, 이 사이트에서만** 확인할 수 있으며 최대 30건까지 보관합니다. 브라우저 저장소가 차단되면 새로고침 후 기록이 유지되지 않을 수 있습니다.

## 4. 신규 인터랙션 시나리오

| 사용자 행동 | 이벤트 | 확인 조건 | 성공 시 화면 반응 | 다른 분기 / 다음 행동 |
|---|---|---|---|---|
| 기존 신청을 확정 | `submit` | 이름·목적·안내 확인 유효 | 완료 화면 + 내역에 새 기록 저장 | 필수값 누락은 기존 단계에서 오류 안내 |
| '내 신청 내역 보기' 클릭 | 링크 클릭 | - | 내역 영역으로 이동 | 내역이 없다면 신청 체험 안내 |
| 캐릭터 이름 검색 | `input` | 검색어 포함 여부 | 일치한 기록만 목록 표시 | 결과 없음 → 검색어 변경 또는 초기화 |
| 상태별 보기 변경 | `change` | 완료·취소·전체 | 해당 상태의 기록만 표시 | 결과 없음 → 상태 변경 또는 초기화 |
| '상세 보기' 클릭 | `click` | 선택한 기록 존재 | 이름·활용 목적·상태·시각 표시 | '상세 닫기'로 목록으로 돌아감 |
| '체험 취소' 클릭 | `click` | 완료 상태인 기록 | 배지 `취소`, 취소 버튼 비활성, 피드백 변경 | 이미 취소한 내역은 다시 취소 불가; 전체/취소 필터로 확인 |
| '검색 초기화' 클릭 | `click` | - | 검색어 삭제, 전체 상태 선택, 목록 복원 | 다음 기록 검색 가능 |

## 6. 프로젝트 구조

```text
UiUxPrograming/
├── index.html                 # 서비스 소개 + 신청 흐름 + 신규 신청 내역
├── style.css                  # 화면, 피드백 상태, 반응형 레이아웃
├── script.js                  # 입력 검증, 이벤트, 저장·검색·조회·취소 처리
├── image/
│   └── virtual-character.png # 이미지
└── README.md                  # 사용자 흐름·시나리오·테스트 기록
```

## 7. 실행 및 배포

1. `index.html`, `style.css`, `script.js`, `README.md`, `image/virtual-character.png`를 같은 GitHub 저장소에 보관합니다.
2. 브라우저로 `index.html`을 열거나 VS Code Live Server에서 실행합니다.
3. 테스트 결과를 실제 상태에 맞게 수정하고 GitHub에 Commit 및 Push합니다.
4. Published Website에서 새 기능이 반영됐는지 다시 확인합니다.

- **GitHub Repository:** https://github.com/mksymphony/UiUxPrograming
- **Published Website:** https://mksymphony.github.io/UiUxPrograming/

> **주의:** 내역은 사용자의 브라우저 저장소에만 저장됩니다. 다른 기기·브라우저와 공유되지 않습니다. 실제 고객 정보나 실사용 개인정보를 입력하지 마세요.

### 제출 전 직접 확인

- GitHub Pages 주소에서 실제 이미지와 새 내역 기능이 표시되는지 확인
- 실제 브라우저에서 1건 신청 후 새로고침하고 내역이 유지되는지 확인
- 모바일 화면에서 탭·버튼의 키보드/터치 조작이 가능한지 확인
- 실제 결과가 다르면 위 테스트 결과를 수정하여 제출
