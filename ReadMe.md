# Virtual Character Studio · 10주차 내비게이션 UI와 정보 탐색

3D 버추얼 캐릭터 제작을 소개하는 **브라우저 시연용 UI/UX 프로젝트**입니다. 실제 제작 신청이나 서버 전송은 하지 않습니다. 기존 6주차 기능 탭, 7주차 5단계 신청, 중간고사 신청 기록 관리, 9주차 조건부 폼 검증과 제출 실패·재시도 기능을 유지합니다.

## 주요 사용자와 사용 목표

- **주요 사용자:** 방송, VRChat, 영상 콘텐츠에 사용할 3D 버추얼 캐릭터가 필요한 사람
- **목적:** 캐릭터 제작 가능 기능을 알아보고, 제작 신청 과정을 체험한 뒤, 이전 신청 내역을 다시 찾아 확인한다.
- **핵심 행동:** 메뉴 이동 → 기능 정보 확인 → 제작 신청(이름·목적·추가 요청) → 결과 저장 → 신청 내역 검색·상세 보기·취소

## 10주차에서 새로 추가/수정한 내용

1. `nav > ul > li > a` 구조의 **주요 메뉴 5개**를 만들었습니다. 각 항목은 실제 페이지의 동일한 ID 섹션으로 이동합니다.
2. 현재 섹션의 메뉴에 **`aria-current="location"`와 빨간색 선택 스타일**을 적용합니다. 메뉴 클릭뿐 아니라 스크롤, 새로고침, 주소의 `#hash` 변경, 브라우저 뒤로 가기에 반응합니다.
3. 화면 너비 **768px 이하에서 메뉴 토글 버튼**을 표시합니다. `메뉴 열기`/`메뉴 닫기` 문구, `aria-expanded`, 메뉴 가시성은 동일한 상태에 따라 변경됩니다. 메뉴 항목을 선택하면 닫힙니다.
4. 신청 내역을 **전체/완료/취소** 버튼으로 필터링합니다. 선택된 버튼은 `is-active`/`aria-pressed="true"`로 구분하고 목록도 함께 갱신합니다. 이름 검색과 필터는 동시에 적용됩니다.
5. 내역 상단에는 **`표시 N건 / 전체 M건`**을 보여줍니다. **전체 내역이 0건인 경우**와 **검색어 또는 필터 때문에 결과가 0건인 경우**에 서로 다른 메시지를 보여줍니다.

## 메뉴와 목적지

| 메뉴 이름 | 목적지 ID | 주요 역할 |
|---|---|---|
| 서비스 소개 | `#about` | 이미지와 서비스 목적 |
| 주요 기능 | `#features` | 기능 카드 3개와 설명 전환 탭 |
| 이용 방법 | `#guide` | 제작 신청 이용 순서 |
| 제작 신청 | `#request` | 이름/목적/조건부 요청 검증, 확인, 제출 |
| 신청 내역 | `#history` | 기록 검색·필터·상세 보기·취소 |

## 정보 탐색 필터 규칙

- `전체`: 완료/취소 상태의 저장된 시연 기록 모두 표시
- `완료`: 현재 상태가 `active`인 기록만 표시
- `취소`: 현재 상태가 `cancelled`인 기록만 표시
- 이름 검색은 부분 일치이며, **현재 상태 필터와 함께 적용**됩니다.
- `검색 초기화`를 누르면 검색어가 비워지고 상태 필터가 전체로 돌아옵니다.
- 상세 정보를 열었다가 필터 조건 때문에 해당 항목이 숨겨지면 상세 화면도 함께 닫힙니다.

## 동작 확인 순서

1. PC 1100px에서 메뉴 5개를 순서대로 눌러 섹션 이동 및 빨간 메뉴 선택 상태(`aria-current`)를 확인합니다.
2. `#history`에서 새로고침 후에도 현재 위치 표시가 맞는지 확인하고, `#features`로 이동한 후 브라우저 뒤로 가기로 `#history`로 복귀되는지 확인합니다.
3. 창 폭을 768px 또는 390px로 줄여 `메뉴 열기` 클릭 → 메뉴 표시, 문구 `메뉴 닫기`, `aria-expanded=true`를 확인합니다. 메뉴를 선택하면 닫히며 값이 `false`로 변경되어야 합니다.
4. 신청 내역이 **비어 있는 브라우저**에서는 `표시 0건 / 전체 0건`과 **신청부터 하라는 안내**를 확인합니다.
5. `제작 신청`에서 이름 2~20자, 활용 목적 선택, 필요하면 8~150자의 추가 요청사항, 시연 안내 체크 후 신청을 완료해 기록을 추가합니다.
6. `신청 내역`으로 돌아가 전체 수와 표시 수가 맞는지 확인하고 `완료`를 누르면 선택 버튼과 목록이 동시에 변경되는지 확인합니다.
7. 기록을 `체험 취소`하고 `취소` 필터로 바꿔 표시되는지 확인합니다. `완료` 필터에서 해당 항목이 제외되는지도 확인합니다.
8. 존재하지 않는 이름을 검색해 **조건 불일치** 안내가 나타나는지, `검색 초기화` 후 다시 전체 목록이 표시되는지 확인합니다.
9. 390px에서 메뉴 버튼·필터 버튼·입력창·기록 카드·상세보기 버튼이 겹치거나 가로로 잘리지 않는지 확인합니다.
10. 9주차 기능(선택적 추가 요청 영역의 `hidden`/`disabled`, 실시간 오류 검증, 제출 중 버튼 비활성화, 실패 후 재시도)이 유지되는지 확인합니다.

## 테스트 결과

Chromium에서 네트워크 접속 없이 HTML·CSS·JavaScript를 직접 로드하고 **58개 항목을 검사해 통과**했습니다. URL의 `#hash` 복원은 브라우저 초기화 시뮬레이션으로 검증했습니다. **실제 GitHub Pages에서 새로고침 및 localStorage 유지 여부는 직접 확인해야 합니다.**

| 확인 항목 | 로컬 테스트 | 배포 페이지 |
