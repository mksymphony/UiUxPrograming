# Virtual Character Studio · 9주차 폼 UI와 입력 경험 설계

본 프로젝트는 **버추얼 캐릭터 제작 신청을 브라우저에서 체험하는 UI/UX 프로토타입**입니다. 실제 신청 접수나 서버 전송은 없습니다. 이전 주차의 소개, 기능 탭, 5단계 신청, 신청 내역 검색·상세 조회·취소 기능을 유지하면서 **9주차에 조건부 입력, 유효성 검사, 제출 중 상태, 재시도 흐름**을 추가했습니다.

## 사용자 / 목적 / 핵심 행동

- 사용자: 버추얼 방송·VRChat·영상 콘텐츠에 활용할 3D 캐릭터 제작을 고민하는 사람
- 목적: 캐릭터 제작 시 필요한 기본 정보를 입력하고, 추가 제작 요청이 필요한 경우 구체적으로 전달하는 과정을 체험한다.
- 핵심 행동: 이름 입력 → 활용 목적 선택 → (선택 시) 추가 제작 요청 입력 → 안내 확인 → 검토 → 제출 완료 → 내역 조회·취소
- 완료 조건: 폼의 검증을 통과하고 완료 화면에 도달하며, 신청 내역에 이름·목적·추가 요청이 반영된다.

## 9주차에서 새로 추가한 기능

1. **조건부 요청사항 입력**: 3단계에서 `추가 제작 요청이 있어요`를 선택하면 `<textarea>`가 보이고 `disabled=false`가 됩니다. 선택을 해제하면 숨기고 `disabled=true`로 바꿉니다. 해제하면 제출할 요청사항이 없으며, 다시 체크하면 작성한 글은 유지됩니다.
2. **실시간 입력 검증**: 캐릭터 이름은 공백 제거 후 **2~20자**, 추가 제작 요청을 선택했다면 공백 제거 후 **8~150자**여야 합니다. 입력 중 글자 수와 조건 충족 문구가 바뀝니다. 오류가 났다가 올바르게 수정되면 오류 표시가 해제됩니다.
3. **제출 중/성공/실패**: 4단계의 `form`에서 `submit` 이벤트로 검증합니다. 제출 중 0.8초간 `제출 중...`을 보여주고 버튼 및 이전 버튼을 잠가 중복 요청을 막습니다. 성공하면 5단계로 이동하고 로컬 신청 내역에 저장합니다. **실패 시연 체크박스**를 켜면 다음 제출을 한 번 실패시켜 안내 문구를 표시하고 **입력값을 유지한 채 다시 시도**할 수 있습니다. 서버 없이 조건부 실패 경로를 재현하기 위한 테스트 기능입니다.
4. **확인 화면 / 내역 연동**: 4단계에 추가 요청 표시, 완료 후 신청 내역 상세 정보에도 추가 요청 표시. 기존에 저장한 기록에는 `추가 요청 없음`으로 보여주는 호환성을 유지했습니다.

## 주요 이벤트와 조건

| 사용자 행동 | 이벤트 | 확인 조건 | 화면 반응 / 다음 행동 |
|---|---|---|---|
| 이름 입력·수정 | `input` | 2~20자 | 글자 수와 유효성 문구 변경, 오류 해제 / 다음 단계 |
| 활용 목적 선택 | `change` | 반드시 하나 선택 | 목적 반영 / 요청 사항 선택 단계 유지 |
| 추가 제작 요청 체크 | `change` | 체크 여부 | 입력 영역 표시·활성화 또는 숨김·비활성화 |
| 추가 요청 입력·수정 | `input` | 체크 시 8~150자 | 글자 수·유효성 문구 변경, 오류 해제 / 내용 확인 |
| 안내 확인 체크 | `change` | 체크 필수 | 버튼 문구와 상태 변경 / 내용 확인 |
| 신청 확정 | `submit` | 모든 필수 조건 | 중복 제출 차단·제출 중 표시 → 완료 또는 실패 재시도 |
| 실패 테스트 체크 | `change` | 선택 시 일회성 실패 | 오류 메시지, 입력 유지, 체크 자동 해제 / 재시도 |
| 이전·다시 시작 | `click` | 이전은 유지, 다시 시작은 초기화 | 수정 내용 재반영 / 새 시연 신청 |

## 실행 및 확인 순서

1. 6주차 기능 탭 3개가 정상 전환되는지 확인합니다.
2. `제작 신청 시작하기` → 캐릭터 이름을 비워 두거나 1글자만 입력한 뒤 `활용 목적 선택하기`를 누르면 현재 단계에 머물고 오류를 보여주는지 확인합니다.
3. 이름을 2글자 이상으로 수정해 오류가 사라지는지 확인합니다.
4. 목적 선택 단계에서 `추가 제작 요청이 있어요` 체크·해제를 반복해 입력 영역이 숨겨지고 비활성화되는지 확인합니다.
5. 다시 체크하고 요청을 1~7자로 작성한 뒤 `내용 확인하기`를 눌러 오류를 확인합니다. 8글자 이상 작성하면 오류가 사라져야 합니다.
6. 목적 및 안내 확인을 마친 다음 내용 확인 화면에서 이름·목적·추가 요청이 올바른지 확인합니다. `이전 · 수정하기`로 돌아가 수정해도 값이 남고, 다시 검토하면 바뀐 값이 표시되는지 확인합니다.
7. `과제 테스트: 이번 제출을 한 번 실패시키기`를 선택한 뒤 `신청 확정하기`를 클릭합니다. `제출 중...` 표시와 버튼 비활성화를 확인합니다. 다음에는 실패 메시지가 나오고 값이 유지되는지 확인합니다. 다시 클릭하면 완료 화면으로 이동해야 합니다.
8. `내 신청 내역 보기` → 해당 기록의 `상세 보기`에서 추가 요청까지 확인합니다. 검색·취소 기능도 이전처럼 동작해야 합니다.
9. `처음부터 다시 시작하기`를 눌렀을 때 입력·요청 체크·오류·진행 상태가 초기화되고 기존 완료 기록은 유지되는지 확인합니다.
10. 1100px·768px·390px 크기에서 가로 스크롤 없이 조작되는지 확인합니다.
